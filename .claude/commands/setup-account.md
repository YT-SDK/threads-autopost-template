# 新しいアカウントの設計

テーマの候補: $ARGUMENTS

本人はスマホで答える。**1回の質問は最大3つ、選択肢つき**で、決まったことから順にファイルへ書く。体験・経歴・決定は本人が言ったことだけを書く（推測で埋めない）。

## 1. テーマと読者（account_profile.md 2〜3章）
- テーマを「誰の、どんな“なんとなく”を、どう言葉にするか」の1行にする。案を3つ出して選んでもらう。
- 成功の条件を本人に確認する：**本人にしか出せない一次情報（体験・判断・観察）がこのテーマにあるか**。ないなら、別のテーマを勧める。
- 読者はライトユーザー前提（post_rules.md B0「2秒ルール」）。読者が「いつ・どんな気持ちで」見ているかを決める。

## 2. 目的・形・収益（1章）
- 匿名か実名か。匿名なら、出さない情報（勤務先・住まい・家族など）を聞き、`ng_words.txt` と `identity_terms.txt` を埋める。
- 他のアカウントとつながりが分かる要素（同じ口ぐせ・同じ図解の色・同じ体験談）を避ける。図解の色は既存アカウントと変える。
- 収益の主軸（note・アフィリエイト等）と導線。PR表記・ステマ規制（post_rules.md L1）の確認。

## 3. 柱と一次情報（4〜6章）
- 柱を3〜6本（`tags` に使う名前）。比率も決める。
- 一次情報 T1〜T4 を本人から聞き取る。

## 4. 書かないこと（7章）と投稿ルールの追加
- post_rules.md の共通ルール（B0〜B10・C1〜C5・L1〜L6）はそのまま使う。テーマ固有の法令・安全（医療・金融・食品表示など）があれば L7 以降に追加する。

## 5. 研究分野（research_domains.json）
- テーマを5〜7の分野に分け、`id`（英小文字）・名前・調べる範囲を書く。出典の例（S/A/B）もテーマに合わせて書く。
- 書いたら `/research` で初回調査を分野ごとに並列で回す。

## 6. 図解の見た目（brand.json）
- 表示名・ハンドル・色（背景・文字・強調色）。既存アカウントと似せない。
- カード置き場の公開リポジトリ（本人が GitHub で作る）を `cards_repo` / `cards_base_url` に入れる。
- テーマに合う絵（`visual`）が必要なら `tools/make_card.py` に足す。

## 7. 型（formats.json）
- `/collect-research` → `/build-formats` で、伸びている投稿から型を3〜5つ作る。データがまだなければ、汎用の型（意外な原因／決め方／数字の読み方／失敗しかけた話）から始める。

## 8. 仕上げ
- `python -m threads_auto validate` と `python -m unittest discover -s tests` を通す。
- docs/new-account.md の残りの手順（Meta の登録・トークン・Actions・定期作成）を本人と進める。
- `require_human_approval` は最初は true のまま。全自動にするかは本人が決める。
